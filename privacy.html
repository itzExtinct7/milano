Privacy Policy

This policy explains how Vinster Multipurpose Bot (“the Bot”) processes information when it is added to or used in a Discord server.

1. Information the Bot processes

Depending on which features a server enables or a user invokes, the Bot may process:

  • Discord identifiers: user IDs, server (guild) IDs, channel IDs and related identifiers needed to respond to commands and associate records with the correct server or member.
  • Member and profile information: usernames, display names, avatars, account creation time, server join time, role information and bot/member status. Welcome and goodbye features use Discord-provided member information to build server messages. Some profile details may be fetched when available.
  • Feature data stored in the Bot database: economy balances and cooldowns; XP and levels; warnings and moderation case references; school tasks; private code snippets; queue entries; configured word filters and their creator IDs; soundboard metadata and uploaded sound files; and server configuration such as welcome, goodbye, auto-role, moderation-log and feature settings.
  • Message content: when a server enables message-based automatic moderation, the Bot processes message text to check configured blocked words or invite links. It does not need message content for ordinary slash-command interactions.
  • Command and operational data: information needed to execute commands, handle errors, maintain service health and create database backups. Operational logs may include event context such as server IDs, command names and error details. The logger is configured to redact selected identifier and credential fields, but this should not be interpreted as a guarantee that every log contains no personal data.

2. Why information is used

Information is used only to provide and maintain Bot functionality, including moderation, welcome/goodbye messages, leveling, economy, queues, school tasks, snippets, soundboard, music integration, configuration, abuse prevention, troubleshooting and security.

3. Where information is stored

The Bot uses a SQLite database on the machine or hosting environment where its operator runs it. Soundboard uploads are stored as files on that host. The operator may create database backup files as part of routine operation and shutdown handling. The operator is responsible for securing the host, database, sound files, logs and backups.

Discord separately processes messages, account information and interactions under its own policies. When music or NSFW image commands are used, the Bot may communicate with the separately configured Lavalink service or the NekoBot.xyz API. Those services have their own infrastructure and privacy terms; the Bot operator does not control their independent data handling.

4. Sharing and third-party services

The Bot does not sell personal information. Information may be processed by Discord to operate the platform, by the Bot host/provider to run the service, and by optional external services that a feature calls (for example, a configured Lavalink node or NekoBot.xyz). Server administrators may see information that the Bot posts in configured welcome, goodbye or moderation-log channels. Do not use private snippets or other Bot features to store passwords, payment details, government identifiers or other highly sensitive information.

5. Retention

Feature records remain in the Bot database until they are changed or deleted through the relevant feature, a user-data deletion request is completed, or the Bot operator removes them. The code creates database backups, so deletion from the live database may not immediately remove copies in backups. The exact backup rotation and deletion schedule depends on the operator’s hosting and maintenance practices and is not currently specified by the Bot code. The operator should configure and document a finite backup-retention period before production use.

6. Your choices and deletion

Users can invoke /privacy delete-my-data in a server where the Bot is present and confirm the deletion prompt. Configured Bot owners can use the owner-only deletion command to erase a user’s Bot-managed records. The implementation targets user-linked records across the Bot database and associated soundboard files. Some moderation records are removed as part of this operation.

Deletion does not remove messages already sent to Discord, records held independently by Discord or third-party providers, server-wide settings, external logs, or backup copies that are not automatically purged. If you need help, contact the operator using the contact details below and include your Discord user ID only when necessary to identify the relevant records. Do not send passwords or authentication tokens.

7. Security

The Bot uses a local SQLite database with foreign-key enforcement, write-ahead logging and secure-delete settings, and its logger redacts selected sensitive field names. No online service or storage method can be guaranteed completely secure. Server owners should restrict access to the Bot host, environment variables, database, backups and logs, and should never publish the Discord bot token.

8. Children and age-restricted features

The Bot is not designed to bypass Discord’s minimum-age requirements. Its NSFW commands are intended only for adults and are gated by server configuration and Discord age-restricted channels. Do not use those commands if you are under 18 or where adult content is unlawful. Server administrators are responsible for configuring channels and complying with applicable rules.

9. Changes to this policy

This policy may be updated when Bot features, infrastructure or legal requirements change. The “Last updated” date at the top will be revised when material changes are made. Continued use after an update means the updated policy applies to subsequent use.
